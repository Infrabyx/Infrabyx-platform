## 5. What each product must change to adopt this release

Applies to Udofin, Finbyx, LawDocs, LawDocsComply, Equator and Operations Hub.

- **New products:** run `pnpm scaffold --product <code> --name <name> --out <dir>` from this repository at a release commit, then follow the generated `CLAUDE.md`: create the repository and its ruleset, set `NPM_READ_TOKEN`, add the integration, NN, container, compose and a11y legs, the git hooks and secret scanning from this repository, and replace the example registry, digests, hosts and identities in `infra/helm` and `infra/terraform`.
- **Existing products:** move every `@infrabyx/*` dependency together to the versions in §6. No new platform migration; `infrabyx-migrate` gains `--db-file <path>` (the chart's migration job reads the URL from the secrets mount). One new setting, `hello.greeting.max_length`, which only the reference module reads.
- **Infrastructure:** deploy with the shared chart `infra/helm/infrabyx-app` and the Kyverno policies, and provision with the OpenTofu `platform` module of your cloud; generate the exit runbook over your production routing file (`pnpm exit-runbook --routing <file>`) and the BOM with each release.
- **Local development:** `pnpm dev:up` runs the full stack on the real adapters; the seed personas' passwords are written to `SEED_CREDENTIALS.md`, which is never committed.
