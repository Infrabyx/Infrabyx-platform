## 5. What each product must change to adopt this release

Applies to Udofin, Finbyx, LawDocs, LawDocsComply, Equator and Operations Hub.

- **Package versions.** Move every `@infrabyx/*` dependency together to the versions in §6. Add the website packages a product's site or console uses.
- **Migrations,** through `infrabyx-migrate`, in its order (… → ai → vidhi → brand → cms → consent → feedback → trust): `brand/0001`; `cms/0001`–`0004`; `consent/0001`–`0002`; `feedback/0001`; `trust/0001`. Run `infrabyx-rls-lint` afterwards. The service readers they add (`svc_consent_sweep`, `svc_feedback_sla`, `svc_trust_sweep`) are created by those migrations.
- **Settings.** 402 keys in the registry; new PL5 keys are under `web.*`, `cms.*`, `pol.*`, `a11y.*`, `fb.*` and `trust.*` with safe defaults. `cms.media.reencode_enabled` is on; a product that re-encodes adds `sharp` 0.35.5 and passes `SharpMedia` to `MediaLibrary` and `BrandStudio`.
- **Help keys.** notify's help keys moved to `hlp.notify.*`; a product that links to the old `ntf.*` help keys updates them.
- **Studio.** Mount the `@infrabyx/ui/studio` screens in the product console behind its own IDENTITY sign-in and AUTHZ policy (see `apps/console`); never ship the fixture personas.
- **Public site.** Copy `apps/public` as the template: the nonce CSP in `proxy.ts`, the webpack build with server externals, the seed module, the journey registry and the `a11y` gate.
