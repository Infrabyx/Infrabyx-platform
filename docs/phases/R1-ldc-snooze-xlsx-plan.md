## A. PR-LDC-46 — snooze a Work Inbox item until a time, order by due time and severity, list by module and record (`workflow` minor, migration `workflow/0005`)

LawDocsComply's own inbox overlay keeps a per-person snooze, a due/severity ordering and a by-record list beside `InboxService`. The request moves all three into the platform. Triage (R1-D-123): snooze is per person and never hides an item past its due time or an escalation; ordering and the list are reads under the existing RLS.

**Who may snooze (no new policy).** The inbox's existing visibility rule (`VISIBLE` in `inbox.ts`, the same rule `markRead` and `resolve` use): the item's user assignee, or any holder of its assignee role, never the principal it excludes (the maker of an approval request). An item outside that rule, or in another tenant, answers `NotFoundError` (404, existence not disclosed, IPB-02-14), as `markRead` does. A snooze is per person: it hides the item from the principal who snoozed it only; for a role item every other holder still sees it. So no one can hide an item from anyone else, and no role check is added.

**Interface** (`packages/workflow/src/inbox.ts`):

- `snooze(ctx, id, until: Date) → { snoozedUntil: Date }`: a kernel mutation. Refusals, in this order: `until` not a valid `Date`, not in the future, or more than `INBOX_SNOOZE_MAX_DAYS` (30) days ahead → `RangeError`; the item not visible to the caller, or resolved → `NotFoundError`; the item escalated (`escalated_at` set) or itself an escalation (`help_key = 'hlp.inbox.escalated'`, the item `escalate` raises for ORG_ADMIN) → `ConflictError` ("an escalation cannot be snoozed"); the item past its due time → `ConflictError`; `until` after the item's `dueAt` → `RangeError` ("a snooze ends no later than the item's due time"). Snoozing again replaces the time (one row per item and person). Ledgered `inbox.item.snooze` (`after: { snoozed_until }`) in the same transaction.
- `unsnooze(ctx, id) → void`: the same visibility rule (`NotFoundError` otherwise); clears the caller's snooze if one is active. Ledgered `inbox.item.unsnooze` (`after: { cleared }`, true when a snooze was active), so an unsnooze of an item that was not snoozed is still recorded.
- `InboxItem.snoozedUntil: Date | null`: the caller's own active snooze, or null.
- `list(ctx, filter)` gains (all optional; the default answer is the same as today's minus the caller's snoozed items):
  - `productModule?: string`, `recordRef?: string` (the by-module and by-record list; either or both, on the existing `inbox_item_record_idx`).
  - `orderBy?: "newest" | "due" | "severity"`: `newest` (default) is today's `created_at desc, id desc`; `due` is `due_at` ascending with no due time last, then severity (critical, warning, info), then newest; `severity` is critical first, then `due_at` ascending (none last), then newest. Ties always end on `id`, so pages are stable.
  - `snoozed?: "exclude" | "include" | "only"` (default `exclude`): `only` is the person's "Snoozed" view.
- `badgeCount(ctx)` leaves out the caller's snoozed items (the badge counts what is in front of them).

**Reappearing at its time with no timer.** The inbox has a timer poller, but a snooze does not use it: every read compares `snoozed_until > now()` in SQL, so an item is back the moment its time passes, whether or not any poller runs, and no timer row or event is written per snooze. The same read treats a snooze as over (the item shows, `snoozedUntil` null) when the item is escalated or its `due_at` has passed, so even a snooze written before an escalation never hides it. Escalation timers are unaffected: a snoozed item still escalates on time.

**Data model and migration** (`workflow/0005_inbox_snooze.sql`, expand-only, new table only): `workflow.inbox_snooze (tenant_id, item_id → workflow.inbox_item(id), principal_id, snoozed_until, cleared_at, created_at, updated_at)`, primary key `(tenant_id, item_id, principal_id)`, a CHECK that `snoozed_until <= updated_at + 30 days` (the bound held in the table too), forced RLS by tenant as `inbox_item`, every column `dataclass:INTERNAL` (ids and times only; no title or personal data), granted `select, insert, update` to `app_rw` and `select` to `app_ro` (no delete: unsnooze sets `cleared_at`). Added to `checksums.json`.

**Tests by IPB ID** (`src/__tests__/inbox-snooze.int.test.ts`, PostgreSQL; `src/inbox.test.ts` unit):

- `@IPB-07-AT-10` / IPB-07-15: hidden from the snoozer's list and badge before its time and back after it (the row's time moved back, no poller run); per person (another holder of the role still sees it); `snoozed: "only"` and `"include"`; `snoozedUntil` on the item; unsnooze brings it back; re-snooze replaces the time; order `due` and `severity` (ties, nulls last) and the default unchanged; the by-module and by-record list.
- Bounds: a past time, now, over 30 days, an invalid `Date` (`RangeError`, nothing written); after the item's `dueAt` (`RangeError`); an item past due, escalated, or an escalation (`ConflictError`); an escalation after a snooze shows the item again.
- Permission (the existing rule): another user, a principal without the role, the excluded maker, a resolved item and an unknown id answer `NotFoundError`, nothing written.
- Tenant isolation: the same item id from another tenant answers `NotFoundError`; a snooze row is invisible across tenants (forced RLS).
- `@NN-45` ledger: `inbox.item.snooze` and `inbox.item.unsnooze` rows in the same transaction (a refused snooze leaves none).
- Unit: the bound constant and the argument checks before any database call.

**Exit checklist:** `workflow` unit, lint, typecheck; the new integration test and the existing `workflow` integration suite; `pnpm migration:lint`; `pnpm ipb:check`; `pnpm aadhaar:scan`; `npx prettier --check .`; the exit runbook check; a Changeset; DECISIONS R1-D-206; OWNER-QUESTIONS #155; threat model §3.147; product guide §7db; the request row marked built.

## B. PR-LDC-52 — the `toXlsx` layout options (`export` minor)

LawDocsComply lays out its registers with its own ExcelJS code on top of the platform's workbook. The request names: row outline levels, fills, frozen columns, AutoFilter, page set-up (A4 landscape, fit to width, repeated header, print area), conditional formats and formula cells. Triage (R1-D-123): on the dependency-free writer, formula cells only as an explicit typed `formula` cell from the product, never parsed from a string; the formula-injection neutralising of text cells stays.

**Formula injection today:** every string cell, header included, passes through `neutraliseFormula` (a leading `=`, `+`, `-`, `@`, tab or carriage return gets an apostrophe) and is written as an inline string, so no cell is a formula. That stays exactly as is: a string from data can never become a formula, even one shaped like the new formula object.

**Interface** (`packages/export/src/xlsx.ts`; all optional, so a workbook that uses none of them is byte-for-byte what the writer produces today, and the existing golden SHA-256 stays):

- `XlsxSheet.freezeColumns?: number` — the first n columns frozen beside the frozen header row (0 to the sheet's column count, at most 16 383).
- `XlsxSheet.autoFilter?: boolean` — an AutoFilter over the header and data rows (with Excel's hidden `_xlnm._FilterDatabase` name for the sheet).
- `XlsxSheet.rowLayout?: readonly (XlsxRowLayout | null | undefined)[]` — per data row (index 0 is the first row under the header): `outlineLevel?: 0..7` (Excel's limit) and `fill?: XlsxColor`. `XlsxSheet.outlineSummary?: "below" | "above"` (default Excel's `below`).
- Fills: `XlsxColumn.fill?: XlsxColor` (the column's data cells), `XlsxSheet.headerFill?: XlsxColor` (the header row), and the row fill above; a row fill wins over a column fill. `XlsxColor` is six hex digits, `RRGGBB`.
- `XlsxSheet.page?: XlsxPageSetup` — `paper?: "A4" | "A3" | "letter" | "legal"` (default A4), `orientation?: "portrait" | "landscape"` (default portrait), `fitToWidth?: boolean` (every column on one page wide, any number of pages tall), `repeatHeader?: boolean` (row 1 printed on every page, `_xlnm.Print_Titles`), `printArea?: string | true` (an A1 range inside the grid, or `true` for the header and data rows, `_xlnm.Print_Area`). Default margins are written with it.
- `XlsxSheet.conditionalFormats?: readonly XlsxConditionalFormat[]` — typed rules only, never a caller's formula text: `{ column, when, style, wholeRow?, stopIfTrue? }`, where `column` names a column by its `key` or header, `when` is a comparison (`lt`, `le`, `gt`, `ge`, `eq`, `ne` with a value; `between`, `notBetween` with `min` and `max`), `containsText` with a text, or `blank` / `notBlank`; a value is a number, a `yyyy-mm-dd` date (on a date or datetime column), text (on a string column; quotes doubled), a boolean (on a boolean column) or `{ today: n }` (today plus n days). `style` is `fill?`, `fontColor?`, `bold?` (a `dxf`). The writer builds the rule's expression itself (`$C2<46023`, `AND(ISNUMBER($C2),$C2<TODAY()+0)`, `ISNUMBER(SEARCH("text",$C2))`) over the column's data rows, or across the whole row when `wholeRow`; rows covered as the validations are (`validationRows`, else the data rows).
- **Formula cells:** `xlsxFormula(formula, { result? })` returns an `XlsxFormula` that a cell of any column type may hold. Only an object made by `xlsxFormula` in the same process is a formula (a module-private `WeakSet`), so a plain object or a string with the same shape from data or JSON is never one. The formula is checked: 1 to 8 192 characters (Excel's limit), no leading `=`, no character XML cannot carry; outside its string literals no `[`, `]` (external workbook references) or `|` (DDE), and none of the functions that reach outside the workbook or run code (`WEBSERVICE`, `IMAGE`, `HYPERLINK`, `RTD`, `CALL`, `REGISTER`, `REGISTER.ID`, `EXEC`, `STOCKHISTORY`, with or without the `_xlfn.` prefix). `result` (a cached value of the column's type) is written as the cell's value; without it, the workbook asks Excel to calculate on load (`<calcPr fullCalcOnLoad="1"/>`, only when a formula is present). Refusal reason `formula_invalid`.
- Refusals stay `OfficeExportError` with a reason: `layout_invalid` (a bad freeze count, outline level, colour, row layout entry, page set-up or print area), `conditional_format_invalid`, `formula_invalid`.

**Styles:** the existing cell styles keep their indexes (0 to 3, and 4 to 6 when a sheet has an editable column); a fill adds fills and cell styles after them in first-use order (sheets, then the header, then rows and columns in order), and conditional styles add `dxfs`, so the same input gives the same bytes. Date and datetime number formats are kept on filled cells, and an editable column's cells stay unlocked when filled.

**Tests** (`src/xlsx-layout.test.ts`; the writer's own tests stay unchanged, including `XLSX_GOLDEN`):

- Each option written as SpreadsheetML in the right element order (the pane and its selections, `autoFilter` and the hidden name, `outlineLevel` and `outlineLevelRow`, `outlinePr`, fills and cell styles, `pageSetUpPr`, `pageMargins`, `pageSetup`, the print names, `conditionalFormatting` with `dxfs`), read back with the package's own `readZip` and `readXlsx` (values, date styles on filled cells, formula results).
- Formulas: typed only (a forged object and a formula-looking string stay text, neutralised); the refusals (leading `=`, too long, external reference, DDE, each blocked function, a bracket or bar inside a string literal allowed); the cached result per type; `fullCalcOnLoad` only with a formula.
- Determinism: the same layout twice gives the same bytes; a workbook with no layout keeps today's golden SHA-256; a layout golden SHA-256.
- Each refusal reason.
- Well-formed XML parts and a clean ZIP (xmllint, unzip, skipped without the tools, as today); where `openpyxl` is installed, the workbook opened with it and the freeze pane, filter, outline levels, fills, page set-up, print titles and area, conditional formats and formulas asserted (skipped otherwise).

**Exit checklist:** `export` unit, lint, typecheck; the existing `export` integration suite and `test:golden`; `pnpm ipb:check`; `pnpm aadhaar:scan`; `npx prettier --check .`; the exit runbook check; a Changeset; DECISIONS R1-D-207; OWNER-QUESTIONS #156; threat model §3.148; product guide §7dc; the request row marked built.

**Owner decisions needed** (#156, none blocking): the blocked function list and the bracket and bar rule (a deny list rather than an allow list); refusing a leading `=` rather than stripping it; `fullCalcOnLoad` when no result is given; conditional formats as typed rules only (no free expression); no collapsed outline groups (levels only).
