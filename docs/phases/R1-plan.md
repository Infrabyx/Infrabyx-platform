**M17 design (R1-D-25).**

- **Registration.** A product's migration calls `select audit.register_capture('<schema>.<table>')` on a table with `tenant_id` and forced RLS. The table gets `ipb_capture` (after insert, update or delete, for each row) and `ipb_capture_truncate` (refuses TRUNCATE), both enabled ALWAYS, so `session_replication_role = replica` does not switch them off. Registration has no undo.
- **What is captured.** One `audit.capture` row per changed row, holding:
  - the table, the operation, the registered key's values, and the before and after values (`to_jsonb`);
  - the application actor, entity, branch, break-glass grant, trace, action and reason, from the kernel's transaction settings;
  - the database login (`session_user`) and role (the `role` setting), the transaction id, and the time (`clock_timestamp`, ms).
- **Writer.** `audit.capture_row()` is SECURITY DEFINER, owned by `capture_writer`. That role logs in nowhere and is granted to no application, read-only, migration or support role. Nobody else can insert, and nobody can update or delete; the refusals are enabled always.
- **Chain.** A per-tenant SHA-256 chain, built as the ledger's is (PL1-C-01): genesis 64 zeros; the canonical form is a sorted JSON object over fields JSON never escapes, with the values, the row key and the reason as digests of their stored text. `verifyCaptureChain` reproduces it in TypeScript. The daily anchor (format 2) signs the capture head of the day with the ledger head.
- **Cannot be disabled.**
  - There is no setting or flag.
  - The `ddl_command_end` guard refuses any DDL that leaves a registered table without its triggers enabled always, disables a capture refusal, or changes `capture_row()`'s owner or security definer.
  - The `sql_drop` guard refuses dropping any capture object, a registered table or its triggers.
  - Event triggers need the database owner's privilege; without the guard installed, `register_capture` refuses.
  - The gap detector (`AuditService.verifyCapture`, daily through `AuditSweep.verifyCaptureAll`) checks the chain, the head and `capture_problems()`, including a disabled or missing guard. It ledgers a break and raises `LedgerChainBroken`.
- **Residual.** A superuser can disable the event triggers and then the refusals; that leaves a chain break or a reported problem, and is visible in PostgreSQL's log. Capture rows are kept as the ledger is (IPB-02-52: eight years, never deleted by the platform).
