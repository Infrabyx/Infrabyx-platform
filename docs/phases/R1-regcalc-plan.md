# R1 — Regulated calculations for the lending products (LDC-66 + PR-FBX-58)

**Status: plan only. Stops for the owner's approval before any code (owner, 27 Nov 2026 07:45 IST, B.5; R1-D-295).**

One combined request: LawDocsComply LDC-66 and Finbyx PR-FBX-58. Finbyx (LMS) and Udofin (DLA) compute these figures for borrowers; LawDocsComply (CT) tests them. One implementation and one set of oracles mean the three agree by construction.

## 1. The package

## 2. Modules, oracles and contract cases

The oracles are the owner's worked examples in `docs/regulatory-models/` (fictitious NBFC). The owner recalculated them in Excel, so every formula cell holds its stored result. A test reads each workbook with `@infrabyx/export`'s bounded XLSX reader (a dev dependency) and asserts that the code reproduces **every output cell**: money to the paisa, rates to 1e-10, flags exactly.

## 3. What stays product-local

- Loan products, fee schedules and the decision of which charges count as upfront or recurring (the product passes cash flows; the package does not know a product's fee names).
- The KFS document itself (DOCGEN, plan (c) of the templates plan), its languages and delivery.
- ECL, IRAC, ALM, ICAAP, stress testing and the business plan (Finbyx's core or LawDocsComply's): not in this request. They can join the package later the same way.
- Where results are stored, ledgered and shown.

## 4. Owner decisions needed

1. **Publish `@infrabyx/regcalc` at 1.0.0** (new package, as `fakes`), with ADR-0015 and a platform request to add it to IPB-14 §14.2?
2. **The APR the KFS shows:** equal periods (as the Annex illustration) by default, with actual dates available and named? Rounding: the APR to two decimals of a percent, half-up?
3. **Rounding of instalments:** the product passes its rule (rupee or paisa, half-up or half-even, last instalment absorbs), with half-up to the rupee as the default?
4. **Error codes:** a new catalogue area `IPB-CALC-*` (a platform request for IPB-01 §01.6.3), or labels on a generic 422?
5. **Default parameter packs:** ship the packs built from the owner's models (with citations and effective dates) in the package, or have each product load them from `docs/regulatory-models` data? Shipping them makes a rule change a package release.
6. **Applicability rule content:** the evaluator and schema in the package, the owner's rule tables (`app*_rules.json`) as the default pack, versioned?
7. **The RBC Annex APR illustration:** the filed KFS-M01 files (worked example, master and `build_pricing.py`) hold no sheet for it, although the models' README lists an "RBI illustration test". This repository does not hold the Directions' text. May the fixture be the Annex's inputs and stated APR, typed into a test with the paragraph cited (figures only, no Annex text), from figures the owner or LawDocsComply supplies?
