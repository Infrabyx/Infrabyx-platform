XLSX and DOCX writers over the package's own ZIP writer, with no new dependency (R1-plan M59; PR-LDC-28). `toXlsx(sheets, { created?, title?, creator?, maxBytes? })` writes a SpreadsheetML workbook: typed columns (`string`, `number`, `integer`, `boolean`, `date`, `datetime`), inline strings with formula injection neutralised (`neutraliseFormula`: a leading `=`, `+`, `-`, `@`, tab or CR gets an apostrophe), never a formula cell, finite numbers only, dates as Excel serials (UTC), a bold frozen header, Excel's sheet-name rules, and refusals past 1 048 576 rows, 16 384 columns, 32 767 characters a cell or the byte cap (64 MiB uncompressed by default). `toDocx({ title?, blocks }, { created?, creator?, maxBytes? })` renders headings 1 to 6, paragraphs of bold, italic, underlined and https-hyperlink runs, bullet and numbered lists with one nested level, plain-text tables and page breaks; no macros, fields or images. Both escape all text, drop characters invalid in XML 1.0, refuse with `OfficeExportError` (`reason`), and give the same bytes for the same input and `created` time. `toCsv` takes an optional `{ neutraliseFormulas: true }` for spreadsheet-bound CSV (off by default, so archive datasets are unchanged). PDF follows in wave 7.
