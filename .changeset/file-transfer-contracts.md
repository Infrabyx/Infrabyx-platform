The FILE_TRANSFER port (Udofin PR-UDF-071, Finbyx's BureauSubmitter its second user; R1-D-254, ADR-0014). `contracts/ports` adds `FileTransferPort`: `list(dir, { maxEntries })` → `{ dir, entries: [{ name, type, size, modifiedAt }], truncated, skipped }`, `get(path, { maxBytes })` → `{ path, bytes, size, sha256 }` (refused `too_large` past the cap, default 32 MiB, at most 256 MiB) and `put(path, bytes, { ifAbsent: true })` → `{ path, size, sha256 }` (no overwrite: refused `exists` when the path exists); every call takes the `PortCall` fields and an `AbortSignal`. Shared checks `fileTransferPath`, `assertFileTransferPath`, `isFileTransferName`, `assertFileTransferClass` (at least the new port default `REGULATED`, never `SECRET`), `preparePut`, `fileTransferGetLimit`, `fileTransferListLimit`, `assertNotAborted`, and the fixed refusal labels `FILE_TRANSFER_REFUSALS` with `fileTransferRefusal`. Catalogue entry `FILE_TRANSFER` (tier 2, `int.file_transfer.`, in `R1_PORTS`) and `PORT_DEFAULT_DATA_CLASS.FILE_TRANSFER = "REGULATED"`. The Ecosystem Spec §3.11 helpers: `fileExchangeName`, `parseFileExchangeName`, `FileExchangeManifest`, `fileExchangeManifest` and `checkFileExchangeManifest` (fixed mismatch labels). Nothing existing changes.
