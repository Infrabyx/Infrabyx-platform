`@infrabyx/connectors/file-transfer`: the FILE_TRANSFER reference adapter `sftp` (Udofin PR-UDF-071, Finbyx's BureauSubmitter its second user; R1-D-254, ADR-0014; C-29 on the owner's instruction, R1-D-249), `SftpFileTransfer` over `ssh2` 1.17.0 (MIT, new runtime dependency; no native addon is built). One connection per call to the product's configured target (`SftpTarget`: host, port, username, pinned `hostKeySha256`, `clientKeySecret`). Before the network: `int.file_transfer.sftp.enabled` (off by default), the target on the India-hosted allow-list `int.file_transfer.sftp.allow_hosts` (`SftpAllowList`, residency `IN`), the path rule and the class. Then: the host resolved once with every answer public (`isPublicAddress`) and the socket to the checked address; the client key from SECRETS checked as one unencrypted OpenSSH `ssh-ed25519` key; public-key authentication only; the host key `ssh-ed25519` and pinned by SHA-256 fingerprint (no trust on first use); fixed algorithms `SFTP_ALGORITHMS` (curve25519-sha256, AES-256-GCM and ChaCha20-Poly1305, no compression) and a fixed identification string; `put` by exclusive create (WRITE | CREAT | EXCL, never TRUNC), a partial file removed on failure; `get` capped before and while reading; a call deadline, a handshake timeout and the AbortSignal; fixed refusal labels only. Health makes no connection unless `healthProbe` is set. Router table entries (`noFailover`), the exit entry (`sftp` → `fake-file-transfer`) and the `FILE_TRANSFER` contract leg. Off and unproven; no migration.
