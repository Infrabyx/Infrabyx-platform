`FakeDocgen` can write real files to STORAGE (Udofin PR-UDF-077, R1-D-259): `new FakeDocgen(templates, { storage, renderers: { pdf: toPdf, docx: toDocx }, bucketClass? })`. Each `render` and `renderHtml` then lays out a document (the template and version as title and level-1 heading, one paragraph per data field in key order; for HTML, its title and block text, never its head, scripts or styles; text outside printable ASCII and the rupee sign shown as `?`), renders it and writes the bytes under the request's prefix as `tenant/<tenant>/<module>/<ULID-shaped id>.<ext>` with the bytes' SHA-256 (`CONFIDENTIAL` by default). `pdf` is plain PDF, `pdfa` asks for PDF/A-2b with PDF/UA-1 (`{ pdfa: "2b", pdfua: true, lang: "en" }`), `docx` needs a `docx` renderer (`IPB-PORT-001` otherwise), `html` writes the escaped page. The id comes from the bytes' hash, so a deterministic renderer gives the same key and bytes for the same request; a prefix that is not `tenant/<tenant>/<module>` is refused before anything is written. The renderers are passed in because `@infrabyx/fakes` cannot depend on `@infrabyx/export` (a cycle through `@infrabyx/testing`). New types `FakeDocgenFiles`, `FakeDocgenRenderers`, `FakeDocgenDocument`, `FakeDocgenPdfOptions`. Without the second argument nothing changes.
