The AA consent's FIU check, approval link and product reference (Udofin PR-UDF-050; R1-D-204). `contracts`: `AaConsentRequest.fiuId?` (the FIU the consent is for, `AA_FIU_ID_REGEX`) and `AaConsentRequest.consentRef` now a `PortConsentRef` (a `cpr_` or the product's own `{ kind, id }`, R1-D-203); `AaConsent.fiuId?` (the FIU the AA reports) and `AaConsent.approvalUrl?` (the AA's customer approval page, only while PENDING); `aaFiuMismatch`, `AA_FIU_MISMATCH` (`fiu_mismatch`), `aaApprovalUrlAllowed` (`https:`, no user information, no 12-digit run or Aadhaar-like number, an exact listed host) and `AA_APPROVAL_URL_REFUSED` (`approval_url_not_allowed`). When a request names a FIU, a consent the AA reports for another FIU, or for none, is refused `IPB-PORT-001` `fiu_mismatch` (definite) before anything is kept or returned, and so is every later read-back (`consentStatus`, `revoke`, `fetch`, `handleWebhook`); a request without `fiuId` is compared with nothing, as before. `connectors` (`SetuAccountAggregator`): reads the FIU from the consent read-back's `detail.FIU.id`, keeps the asked FIU in `SetuConsentRecord.fiuId`, answers Setu's link as `approvalUrl` while PENDING only after `aaApprovalUrlAllowed` against the new `approvalHosts` option (default Setu's two hosts), reads the consent back before keeping its record so a refused one leaves none, and deprecates `approvalUrl(consentId)`. `fakes` (`FakeAccountAggregator({ fiuId?, approvalHost? })`) reports its own FIU (`fake-fiu`) and a letters-only link while PENDING, with `reportFiu` and `consentsKept` test hooks; `AccountAggregatorFixtures` gains optional `fiuId` and `reportFiu`. `testing` adds the AA contract cases (both consent forms, the FIU refusals, the link only while PENDING, an Aadhaar-like sweep) and the Setu stub's `fiuId`, `reportFiu` and `linkBase` hooks (its ids never end in an all-digit group).
