The Studio page editor gains a visual block editor (platform request PR-038, R1-D-02). `ContentEditScreen` takes `blocks: { options, action }`: for a body with blocks it shows each block with its own form (text, numbers, choices, lists of items with a blank row to add and a checkbox to remove, optional groups such as buttons, tables, and rich text written as paragraphs), buttons to move a block up or down or remove it, and a form to add a block of any type at any position. Everything is a plain form post, with no JavaScript. `blockHandlers(cms, options).blocks` applies one operation to the blocks of the current revision and saves the result through `saveDraft`, so the service checks the whole body and voids approvals as before; a post made against an older revision is refused, and the service's field errors land on the field they are about. A block type without a form (tabs) keeps a JSON field, and the whole body stays editable as JSON under "Edit the whole body as JSON". New help keys `hlp.studio.block_*` and `hlp.studio.rich_text` are in the platform registry. Products mount the new action next to `save` (the reference console posts it to `/studio-actions/pages/blocks`).
