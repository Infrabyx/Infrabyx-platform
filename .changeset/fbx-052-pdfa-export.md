PDF/A-2b from `toPdf` (PR-FBX-52, R1-D-248), opt-in: `toPdf(doc, { created, pdfa: "2b", lang })` writes an XMP metadata stream (pdfaid part 2, conformance B; `xmp:CreateDate`, `ModifyDate` and `MetadataDate` from `created`, never the clock; `xmpMM:DocumentID` and `InstanceID` from the same content digest as /ID), /ModDate equal to /CreationDate, an sRGB output intent with the bundled CC0 profile (`icc/`), printable link annotations with a description, and a tagged structure for IPB-06-26 (/Lang, /MarkInfo, a structure tree of H1 to H6, P, L/LI/Lbl/LBody, Table/THead/TBody/TR/TH (column scope)/TD and Link with marked content; rules and repeated table headers are artifacts). `pdfua: true` also claims PDF/UA-1, for a titled document whose headings start at H1 and skip no level (`block_invalid` otherwise). The same blocks, options and `created` give the same bytes, in any process; veraPDF 1.30.3 passes PDF/A-2b and PDF/UA-1 in the integration suite. Without `pdfa` the output is byte-identical to 1.8.5 (`lang` is read only with `pdfa`). New refusal `pdfa_invalid` (an unknown `pdfa`, a bad `lang`, `pdfua` without `pdfa`). `renderPdf` passes `pdfa` and `lang` to the in-process path; `PDF_LANG_TAG` is exported.
