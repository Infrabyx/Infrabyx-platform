Udofin PR-UDF-079 (R1-D-270): Udofin's three extra no-Aadhaar checks are in the shared detector, **on by default with no switch to turn them off**. **Behaviour change, stricter: your CI may newly fail.** Fix the data or rename the column or label; do not drop the check (a column you must keep is skipped by name with `skip: ["schema.table.column"]`, as before). (1) `sweepDatabaseForAadhaar` / `scanDatabaseForAadhaar` report every column named like a carrier (`isAadhaarCarrierName` from `@infrabyx/contracts/aadhaar`) as a `COLUMN` find from the catalogue, with no row read and whatever it holds (`ctid: ""`, `masked: "(column)"`); not a `boolean` column and not a last-four column (`aadhaar_last_digits`, `aadhaarLast4`). A sweep that read no row now returns its finds instead of rejecting `AadhaarScanEmptyError`, which it still does when it found nothing. (2) The `FIELD` rule for columns and JSON keys uses the wider names: `borrower_aadhaar_ref`, `masked_aadhaar_no`, `kyc_uid_token`, `user_uid`, `uidai_token`, and a last-four column or key holding more than four digits. (3) A carrier name followed by a value in free text is a `LABELLED` find (`masked: "(value withheld)"`, at the label): in `scanTextForAadhaar`, `scanPathsForAadhaar`, the `infrabyx-aadhaar-scan` CLI (`file:line: LABELLED (value withheld)`, exit 1) and the database sweep's text values and JSON strings; masked values (`Aadhaar No. XXXX XXXX dddd`) and numbers that fail Verhoeff count. `allow` and `--letters` do not affect it. Types widened: `AadhaarTextFindKind` (`AADHAAR`, `VID`, `LABELLED`) on `AadhaarTextFind.kind`, and `AadhaarDatabaseFindKind` gains `COLUMN` and `LABELLED`.
