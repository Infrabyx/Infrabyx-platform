Chain lanes for the audit ledger and the statutory capture (Finbyx PR-FBX-32; IPB-02-51; ADR-0005; R1-D-58). Each tenant's two chains become 32 lanes (`audit.lane_setting`, raised only with `audit.set_chain_lanes`), so up to 32 of a tenant's transactions append at once instead of queuing on one head row. Each lane is the same SHA-256 chain (PL1-C-01) with the lane and the position (`lane`, `lane_seq`) hashed. A transaction takes a free lane (`FOR UPDATE SKIP LOCKED`) and keeps it until it ends. `seq` becomes a global sequence: unique and increasing in each lane, but no longer a count. Existing chains continue as lane 0 and nothing written is changed. Migrations `audit/0006` (lane heads, sequences, triggers; briefly locks the ledger and the capture) and `audit/0007` (two unique indexes, built concurrently). `verifyChain` and `verifyCaptureChain` verify lane by lane and return `lanes` (`head.hash` is now `lanesRoot`). `AuditService.verify` and `StatutoryCapture.verify` also compare each lane's end with its stored head, so a deleted tail is reported. Anchors are format 3 (`ANCHOR_FORMAT_LANES`: every lane head of both chains), and verification accepts formats 1 to 3. New exports: `lanePosition`, `lanesRoot`, `laneHeadMismatch`, `captureLanes`, the `LaneHead` type. Run `infrabyx-migrate`.
