# @infrabyx/crypto

The only cryptography call-site of the platform (IPB-12-05). Every hash, MAC, signature, key and random value is created here, using Node's built-in `node:crypto` only (PL1-C-09). A future PQC or FIPS change touches this one package. Other packages are blocked from `node:crypto` and Web Crypto by the `ipb/no-direct-crypto` lint rule.

**Specified by:** `docs/ipb/` — IPB-02 §02.4.3.2 and §02.4.7.1, IPB-11 §11.4.7, IPB-12 §12.6 item 1; decisions PL1-C-01 to PL1-C-10 and PL2 C-11, C-13, C-19, C-21 (PL2-C-02, PL2-C-04). Plans: `docs/phases/PL1-plan.md` §5, `docs/phases/PL2-plan.md` §9.

| Area                     | API                                                                                                                                           | Choice                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Canonical JSON           | `canonicalize()`                                                                                                                              | RFC 8785 JCS                                                                                                                                                                                                                                                                                                                                                                          |
| Hash                     | `sha256()`, `canonicalDigest()`                                                                                                               | SHA-256                                                                                                                                                                                                                                                                                                                                                                               |
| MAC / pseudonyms         | `hmacSha256()`, `pseudonymise()`, `hashedActorId()`                                                                                           | HMAC-SHA-256 (C-02)                                                                                                                                                                                                                                                                                                                                                                   |
| Field encryption         | `FieldEnvelope`, `fieldAad()`                                                                                                                 | AES-256-GCM, 96-bit nonce, 128-bit tag; per-tenant data keys cached ≤ 5 min, rotated after 2^20 uses (C-04)                                                                                                                                                                                                                                                                           |
| Blind index              | `blindIndex()`                                                                                                                                | HMAC-SHA-256, separate tenant-scoped key, normalised input (C-05)                                                                                                                                                                                                                                                                                                                     |
| Blind-index keys         | `loadBlindIndexRoot()`, `tenantBlindIndexKey()`, `BlindIndexer`, `localBlindIndexRoot()`                                                      | The product's root key from SECRETS (`blindIndexSecretPath`), an HKDF-SHA-256 sub-key per tenant and scope (`<product>/<scope>/v<n>/<tenant>`), versioned for rotation and re-index (PR-FBX-25, R1-D-37)                                                                                                                                                                              |
| Signatures               | `signRecord()`, `verifyRecord()`                                                                                                              | ECDSA P-256 / SHA-256 via the KMS port; records `alg`, `key_id`, `created_at`, `cert_chain_ref` (C-03)                                                                                                                                                                                                                                                                                |
| IDs                      | `newId()`, `deterministicId()`                                                                                                                | ULID from `randomBytes`; seed IDs from SHA-256 of namespace and natural key (C-06, C-07)                                                                                                                                                                                                                                                                                              |
| Seed passwords           | `generateSeedPassword()`                                                                                                                      | IPB-11 §11.4.7 exactly (C-08)                                                                                                                                                                                                                                                                                                                                                         |
| Registry                 | `ALGORITHMS`, `assertApproved()`, `cbom()`                                                                                                    | CycloneDX 1.6 CBOM, published only when `fut.cbom-export` is ON                                                                                                                                                                                                                                                                                                                       |
| Dev KMS                  | `LocalKms`, `devKeyFingerprints()`, `matchesDevKey()`                                                                                         | HKDF-derived dev keys from a public seed; `dev-keys.json` holds fingerprints only (C-10)                                                                                                                                                                                                                                                                                              |
| JWT/JWS (C-11)           | `verifyJwt`, `verifyJws`, `JwksCache`, `jwkToVerifyKey`                                                                                       | ES256 (P1363) and PS256 (MGF1-SHA-256, salt 32) only, per-issuer allow-list; `none`, HS* and other algs refused; `kid` required; `crit`, `jku`, `x5u`, `x5c`, `x5t`, `jwk`, `b64` refused; strict base64url; RSA ≥ 2048; `iss`/`aud`/`exp`/`nbf`/`iat` ±60 s; JWKS 24 h, unknown `kid` refetched at most once a minute. `jose` is a test-only devDependency for the differential test |
| Vendor signatures (C-13) | `verifyRazorpaySignature`, `verifyCashfreeSignature`, `verifyMetaSignature`, `verifyStandardWebhook`, `verifySnsMessage`, `snsCertUrlAllowed` | HMAC-SHA-256 as each vendor defines, constant-time on raw bytes, ±5 min Cashfree window; Standard Webhooks `v1` only (IPB-10-21; R1-D-199, #150); SNS SignatureVersion 2 only, certificate host pinned to the allowed regions, TopicArn checked                                                                                                                                       |
| Webhook secrets (C-19)   | `generateWebhookSecret`                                                                                                                       | 32 random bytes, base64url                                                                                                                                                                                                                                                                                                                                                            |
| Telemetry IDs (C-21)     | `telemetryIdHasher`, `deriveSubKey`                                                                                                           | HKDF-SHA-256 under `ipb/telemetry-id/v1`, HMAC truncated to 128 bits                                                                                                                                                                                                                                                                                                                  |
| Webhook receiver (C-13)  | `StandardWebhookReceiver`                                                                                                                     | `verifyStandardWebhook` plus a body limit (64 KiB default), one or two secrets (rotation), a window of at most 300 s, and a replay claim after verification (`delivery` key: id and timestamp; `event` key: id only); fixed refusal labels (PR-UDF-064, R1-D-238)                                                                                                                     |
| Partner mTLS             | `readClientCertificate`, `PinnedCaSet`                                                                                                        | From the TLS socket or the edge header (`docs/platform/mtls-edge-header.md`): exactly one leaf, `x5t#S256` (RFC 8705), validity, client-auth usage, and an optional pinned-CA check (ECDSA P-256 issuer signatures only, at most two configured intermediates, no CRL or OCSP); `@infrabyx/crypto/mtls-test` makes throwaway test certificates (PR-UDF-064, R1-D-238)                 |
| Partner mTLS outbound    | `checkClientCredential`                                                                                                                       | The platform's own client certificate and key before `PartnerMtlsClient` uses them: both parse, the key is ECDSA P-256 and the certificate's, a client-auth leaf, valid now; answers the dates and `x5t#S256`, never the key (PR-UDF-069, R1-D-250)                                                                                                                                   |

| PAdES/CMS verify (C-28) | `verifyPadesSignatures`, `CCA_INDIA_TRUST`, `customTrustStore` (tests), `@infrabyx/crypto/pades-test` | Verify only (owner answer #162, R1-D-246): CAdES- or PKCS#7-detached signatures in a PDF; ByteRange coverage, the CMS signature over the signed attributes, the chain to a pinned CCA India root (CCA India 2022 and 2022 SPL, owner answer #178) through intermediates carried in the signature's CMS set under RFC 5280 path checks within fixed work bounds (`chainSha256` reports the path), validity at the signing time, key usage, a B-T timestamp (`requireTimestamp` refuses a signature without one), revocation from caller-supplied CRLs and OCSP only; RSA PKCS#1 v1.5/PSS SHA-256/384/512, ECDSA P-256/SHA-256 and P-384/SHA-384; SHA-1 and MD5 refused. Own strict DER reader, no ASN.1 dependency (R1-D-246, R1-D-272) |
| Signer certificate summary (PR-UDF-070) | `signerCertificateSummary`, `padesSignerCertificates` | Field reading for ESIGN signature records (R1-D-251): a certificate's serial, issuer, validity, SHA-256 of the DER and subject CN; and the certificate each embedded PDF signature is bound to (C-28's ByteRange, digest and CMS signature checks), with no trust judgement. No new algorithm |

`LocalKms` is for `local`, `dev` and `test`. `@infrabyx/config` refuses the `local` KMS adapter, and any configured value matching a dev-key fingerprint, in staging, demo, pre-prod, prod and dr (IPB-11-17).

Scripts: `pnpm --filter @infrabyx/crypto cbom` prints the CBOM; `dev-keys [--check]` regenerates or checks `dev-keys.json`.
