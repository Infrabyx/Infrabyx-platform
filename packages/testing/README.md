# @infrabyx/testing

The test kit every product installs as a devDependency (runtime fakes for fixture environments come from `@infrabyx/fakes`, which this package re-exports unchanged; PR-FBX-48, R1-D-181): a PostgreSQL test database with the platform migrations, context builders, port fakes, the NN pattern suites, the port contract harness, `migration-lint`, the acceptance-test report and the IPB ESLint plugin.

**Specified by:** `docs/ipb/` — IPB-01 §01.4.2, IPB-01-15 (port contracts), IPB-09-31 and §09.4.6.2–3 (migration lint), IPB-14 §14.5 item 4 (NN suites). Plan: `docs/phases/PL1-plan.md` §10. Decisions PL1-D-02 (D-05: lint rules published here), PL1-D-04 (NN tags).

## Database

`startPostgres({ migrations? })` creates a fresh database, applies the platform migrations (tenancy → audit → config → seed → connectors) then the product's, and returns `{ pool, admin, kernel, audit, end }`. With `IPB_TEST_PG_URL` set (CI's PostgreSQL 18 service with pgvector) it uses that server; otherwise it starts the pinned `pgvector` image (PostgreSQL 18 with pgvector) through Testcontainers. `APP_ENV` defaults to `test`. `beforeDrop(admin)` (PR-UDF-042) runs in `end()` before the database is dropped, with the superuser client; if it throws, `end()` still drops the database, then rejects with the hook's error. `end()` is idempotent (PR-UDF-063): a second call, later or concurrent, returns the first call's promise, so the hook and the drop run once.

## No-Aadhaar sweep (PR-UDF-042, PR-UDF-063, PR-UDF-079)

The platform's shared rule (`findAadhaarLike` in `@infrabyx/contracts/aadhaar`: 12-digit Aadhaar numbers, first digit 2 to 9, and 16-digit VIDs, Verhoeff-checked, plain or grouped in fours) over files and databases; a find is masked (`XXXX XXXX dddd`), never more. The sweep joins letters to digits (so a hex hash or base64 run is not a number; `--letters boundary` reads as the AI gateway's scrubber) and blanks a UUID first when it stands alone (no letter or digit next to it, and no four-digit group joined to it by one space or hyphen). Look-alikes (`+91` and ten digits, digits next to a decimal point) are finds unless you pass `allow` / `--allow e164_in,decimal`: your product's choice, and its risk.

- `infrabyx-aadhaar-scan [--letters join|boundary] [--max-bytes N] [--allow e164_in,decimal] <file or directory>...` prints `file:line: KIND masked` for each find. Exit status: **0** every file read and nothing found; **1** a find; **2** nothing proven (a usage error, no file read at all because the paths hold only empty or skipped directories or skipped files, or a file that could not be read). It skips `node_modules`, `.git` and `dist` directories, symbolic links, binary files (a NUL byte in the first 8 KiB) and files over 5 MiB (`--max-bytes`), naming each skipped file on stderr. `--help` lists all this. The platform's CI runs it as `pnpm aadhaar:scan` over its fixtures, recorded stubs and golden sets.
- `scanDatabaseForAadhaar(admin, { skip?, allow?, maxRows?, allowEmpty? })` (also `@infrabyx/testing/aadhaar-scan`) reads every column of every type (each as its text form; `bytea` as hex and decoded) of every table outside the system schemas: `startPostgres({ beforeDrop: async (admin) => expect(await scanDatabaseForAadhaar(admin)).toEqual([]) })`. A column or JSON field named like an Aadhaar carrier (`isAadhaarFieldName`: `aadhaar`, `aadhaar_number`, `uid`, `uid_token`, ... in any case) that holds a value is a `FIELD` find, whatever the value (`masked: "(value withheld)"`, `field` the JSON key path). It rejects with `AadhaarScanEmptyError` when it reads no table or no row (`allowEmpty: true` passes) and with `AadhaarScanLimitError` past `maxRows` (default 100 000). `sweepDatabaseForAadhaar` returns `{ finds, tables, rows }`.
- **Three stricter checks, always on (PR-UDF-079):** (1) every column named like a carrier is a `COLUMN` find from the catalogue, with no row read and even when every value is null (`masked: "(column)"`; not a `boolean` or last-four column); a sweep with finds and no row returns them instead of rejecting; (2) carrier names inside longer names count for columns and JSON keys (`isAadhaarCarrierName`: an `aadhaar`/`aadhar` segment anywhere, or a name ending with `uid`, `uid_no`, `uid_num`, `uid_number`, `uid_token` or `uidai_token`; `user_uid` yes, `uid_kind`, `uuid`, `guid`, `fluid` no), and a last-four name (`aadhaar_last_digits`, `aadhaarLast4`) counts only past four digits; (3) a carrier name followed by a value in free text (`aadhaar: <digits>`, `Aadhaar No. XXXX XXXX dddd`, `uid=<eight or more>`) is a `LABELLED` find, masked or not, in files, the CLI and text or JSON string values (`findAadhaarLabelledValues`). Fix the data or the name; `skip` a column only when it truly holds no Aadhaar.

## Port contract harness (IPB-01-15)

`defineContractSuite("STORAGE", () => new S3Storage(...))` runs the common conventions (descriptor, `health()`), the built-in cases for that port (SECRETS versions, KMS round-trip and signatures, STORAGE write-once retention and `IPB-STOR-003`, FEATURE_FLAG defaults and snapshot) and any adapter-specific cases. Fakes: `MemorySecrets`, `fakeKms()` (LocalKms), `MemoryStorage`, `MemoryFlagProvider`, `MemoryIdentity`.

PL2 additions (plan §3.11, §7):

- `defineContractSuite(port, factory, cases, { leg })` takes the leg: `unit`, `hermetic` or `sandbox`. It checks that an adapter's residency can carry its own maximum class. A case that names a `method` the adapter declares `unsupported` must throw `IPB-PORT-001` with `meta.reason: "unsupported"` (PL2-D-21).
- `startService(name, opts)` starts a pinned image from `TEST_IMAGES` (digests in `infra/docker/TEST_IMAGES.md`), or reuses the service named by `IPB_TEST_<NAME>_URL`.
- `sandboxLeg(adapter, names)` reads `IPB_TEST_SANDBOX_<NAME>` variables. It skips the leg when they are absent, and fails instead when `IPB_TEST_SANDBOX_REQUIRED=true` (nightly, pre-release; IPB-DEV-04). It names missing variables only, never values.
- `startFaultProxy(target, plan)` injects failures or delay in front of a stub or vendor sandbox (`@IPB-01-AT-08`).
- The ESLint rule `ipb/port-data-class` refuses a port call whose literal `dataClass` is below the port default, and a port payload schema field without a data-class annotation (PL2-D-03).

## migration-lint (IPB-09-31)

`infrabyx-migration-lint <migrations dir>... [--contract-label] [--record-checksums]` parses every `NNNN_*.sql` with the real PostgreSQL 18 parser (`libpg-query`) and applies every rule of IPB-09 §09.4.6.2 (`ext-whitelist`, `no-engine-specific`, `rls-required`, `data-class-tag`, `index-concurrently`, `no-expand-contract-same-release`, `not-null-two-step`, `fk-not-valid`, `lock-timeout-set`, `no-data-in-ddl`, `rename-forbidden`, `type-change-forbidden`, `drop-requires-contract-label`, `checksum-immutable`, `audit-ledger-untouched`, `object-lock-untouched`) and every forbidden operation of §09.4.6.3 (`forbidden`, no override). Findings carry `IPB-ENG-004`, `IPB-ENG-005` (edited released file, from `checksums.json`), `IPB-DB-001` (extension) or `IPB-DB-002` (engine-specific). A file that must run outside a transaction (`CREATE INDEX CONCURRENTLY`) starts with `-- infrabyx:no-transaction`. `--record-checksums` adds new files to `checksums.json`; existing entries are never rewritten.

- `@infrabyx/testing/eslint`: the IPB ESLint plugin (`ipb/vendor-import`, `ipb/schema-boundary`, `ipb/no-process-env`, `ipb/no-direct-crypto`) for product `eslint.config.mjs` files; rule tests in `eslint/rules.test.mjs`.
